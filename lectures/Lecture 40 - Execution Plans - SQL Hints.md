## What is Execution Plan

Roadmap generated by a database on how it will execute your query step by step.

It will show all steps and where it might face performance issues

## Estimated Executions Plan

predicts the execution plan without actually running the query

## Estimated vs Actual Plans

If the predictions don't match the Actual execution plan, this indicate issues like inaccurate statistics or outdated indexes, leading to poor performance

## Types of Scan
### Table Scan

Reads the entire table, page by page and row by row "everything" which can lead to slower query performance on large tables

### Index Scan

Scans all data in an index to find matching rows

### Index Seek

A targeted search within an index, retrieving only specific rows

## Join Algorithms

| Join Name        | Description                                             |
| ---------------- | ------------------------------------------------------- |
| **Nested Loops** | Compares tables row by row; best for small tables       |
| **Hash Match**   | Matches rows using a hash table; best for large tables  |
| **Merge Join**   | Merge two sorted tables; efficient when both are sorted |

## SQL Hints

Commands you add to a query to force the database to run it in a specific way for better performance
### Tips

After creating a new index, check the execution plan to see if your query uses the index

1. Test hints in all project environments (DEV, PROD) as performance may vary
2. Hints are quick fixes (Workaround not Solutions) you still have to find the cause and fix it
